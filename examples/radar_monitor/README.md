# 雷达实时监测页面

本机网页加串口采集服务，兼容`rx5-uart-2`诊断固件和启用可选雷达的语音固件，读取COM13控制台。保持ESP32现有接收引脚、波特率及雷达配置，不复位、不清计数、不烧录。服务被动读取固件自行打印的状态，不再自动发送`radar history`，避免十六进制数据刷屏和额外的控制台工作。编译选项见[可选雷达固件.md](../../可选雷达固件.md)。

接线为雷达TX→GPIO6，雷达RX→GPIO8（不驱动），115200、UART2。集成语音版默认并始终使用GPIO6；旧独立demo重启会恢复默认GPIO5，需要手动切换。页面显示实际接收引脚，服务不会自动修改引脚。

## 使用

当前服务地址：[http://127.0.0.1:18888](http://127.0.0.1:18888)。电脑通过CH343 UART口连接设备，串口是COM13。页面只在本机访问，不依赖4G、MQTT或语音服务。

从项目根目录运行以下脚本可隐藏启动后台服务；已有本项目采集进程时会返回其地址：

```powershell
.\examples\radar_monitor\start.ps1
```

或前台启动，按Ctrl+C停止：

```powershell
F:\Espressif\python_env\idf5.4_py3.11_env\Scripts\python.exe examples/radar_monitor/monitor.py --port COM13 --http-port 18888 --output build/radar-monitor-manual
```

停止当前后台采集，日志保留：

```powershell
.\examples\radar_monitor\stop.ps1
```

采集期间此服务独占COM13。关闭网页或暂停网页刷新不会停止记录；另一个串口工具不能同时打开该端口。USB断开后服务会等待同一CH343设备重连，不扫描或切换到其他设备。电脑或采集进程停止后需要重新启动服务，本程序不安装自动启动任务。

## 页面数据含义

- 最近存在状态：仅由长度、帧尾和累加校验通过的`80 01`报文确定。`00=无人`、`01=有人`。没有新报文时保留最近上报，不按超时自动变为无人；检测到雷达初始化消息、接收引脚/波特率变化或ESP32计数重置时回到未知，等待新的有效存在上报。
- 有效报文：从512字节历史快照中重组完整帧。按设备接收字节偏移去重，重复读取同一历史或重叠快照不重复计数。坏校验、错误长度、缺少帧尾的字节不会改变存在状态。
- 历史快照：服务启动/设备会话变化后首次读到的旧报文。表格时间是服务发现时间，无法还原每一帧的原始发送时间。后续新发现报文也可能在最近5秒内发出，不表示精确的页面发现时刻。
- 距最近收到字节：设备最后接收时间，不等于最近存在状态变化时间；USB断开时不计算新的设备接收时间。
- 本次新增字节：监测服务建立基线之后的计数增长，包含无效字节。设备当前累计值包括连接前收到的数据。
- UART错误：设备的溢出、帧、奇偶错误等计数；RX长时间低电平的BREAK在页面另行累计。

参考协议见[R24DVD1用户手册V1.6](https://github.com/blakadder/berry-drivers/blob/main/R24D/datasheet/R24DVD1_User_Manual_V1.6%20en-US.pdf)。已抓到的报文与该存在检测协议一致，尚未读取完整型号或固件版本，也未验证心率/呼吸测量。

## 日志与验证

日志在页面底部显示的本地目录，亦记录于主项目`build/radar-monitor-service.json`：

- `console.bin`：串口原始输出。
- `console.log`：带电脑读取时间的控制台日志。
- `frames.jsonl`：校验通过且去重的帧记录。
- `state.json`：约每2秒保存页面状态。

串口日志及运行记录位于Git忽略的build目录。页面可导出当前记录JSON，保留最近120条帧及200条控制台行；更完整内容在上述日志文件。

被动模式优先显示固件 `STATUS` 中的已校验帧计数和生命体征摘要，原始帧表只有固件实际打印原始记录时才更新。摘要时间是打印时间，不能当作每个测量值的采样时间；没有精确最后接收时间时显示未知。当前短时接收成功不能代替长期检测准确率或供电稳定性测试。
