# TTL 实时日志工具

双击桌面“TTL实时日志”，或者在项目根目录运行：

```powershell
./examples/serial_log_viewer/start.ps1
```

页面地址为 <http://127.0.0.1:18891>。启动脚本确认当前 COM13 采集程序运行，然后启动日志页面。工具跟随采集程序保存的完整 TTL 日志，不与采集程序争用串口，不修改固件或发送通话命令。设备断开后，原采集程序会等待同一设备重新连接。

首页默认显示“通话测试记录”，通过页签切换到TTL实时日志。这是本机测试工具，读取现有 `build/*/state.json` 和各次尝试的结果，不改动正式App或服务器。

- 显示呼叫启动、接通、测试结束时间和通话时长，统一按北京时间显示。已有设备呼出命令使用实际命令时间；缺少发起时间的旧记录使用测试启动时间（含初始化），缺失时间显示“未记录”。测试结束时间含挂断收尾，不冒充精确挂断时间。
- 当前通话每秒计时，记录每5秒更新；测试状态45秒未更新或页面请求失败时暂停实时计时并提示待确认。
- 按测试批次、正式轮次、通过、接通后失败、未接通、已排除中断筛选，并支持时间和原因搜索。展开单条记录查看原始错误、失败时间、关键日志和供电测试条件。
- 有效轮次只统计已接通且未被标记为电脑／服务器中断或计划更换固件的记录。未接通尝试单列；中断保留证据、排除正式轮次。AFE溢出等已观察事件与尚未确认的底层原因分开显示。
- AFE告警后仍观察到双向音频、随后测试程序发出挂断的记录，会明确标记“测试程序主动挂断”，详情显示挂断指令时间和告警后音频持续秒数。原验收失败统计保留，不将它直接解释为设备自行断线。
- `/api/calls` 仅提供经过选择的摘要字段，不返回测试固件配置、完整音频数组或连接凭据。读取过程中不持有日志文件，不控制测试进程。

- 每 0.5 秒刷新，可筛选通话、4G/MQTT、错误警告，也可搜索任意文字。
- 空白行、只有时间戳的行不会显示或占用页面最近 4,000 行的额度；原始日志文件保留。
- 暂停查看只冻结显示，后台继续写入。关闭网页也继续保存。
- “清空日志”清空当前显示，随后继续显示新输出；已保存文件保留。雷达原始数据和周期摘要默认隐藏，可分别勾选展开。来电、接通、挂断、网络变化、错误记录正常显示。
- 音频包计数、正常保活发送、完整 MQTT 消息和 ICE 参数默认收起；勾选“详细调试输出”展开。错误与警告继续显示，完整记录保存在电脑文件中。
- 页面显示最近 4,000 行；“下载完整日志”下载当前文件已有的全部记录。
- 页面顶部显示保存路径、文件大小和最后写入时间。日志位于项目 `build/radar-monitor-日期时间/console.log`；原始串口字节另存为同目录 `console.bin`。
- 下拉框可查看以前的采集记录；实时模式比较通话采集的 `build/esp32-real-call-live.log` 与 `build/radar-monitor-service.json` 指向的日志，跟随最近更新者，避免旧雷达服务配置把实时页面固定到历史文件。

日志仅保存在本机被 Git 忽略的 `build/`，可能包含设备标识及通话连接凭据，请勿直接公开上传完整文件。

本工具的 Web 服务只监听本机。后台记录依赖电脑和采集程序持续运行；电脑重启后双击快捷方式重新启动。
