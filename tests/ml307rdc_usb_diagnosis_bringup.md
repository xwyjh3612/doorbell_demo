# ML307R-DC 新板到货与 USB 诊断

用户已购买图片中的 Luat ML307R-DC 小板。图片可见 D+、D−、TX、RX、GND、VCC 等引出，但不能仅凭图片确认板载稳压、串口电平转换、USB VBUS 接法或出厂固件。该板先用于独立对照和内部日志采集；现有 ML307R-DL 的 40 轮统计继续单独保存。

## 到货后先确认

1. 记录完整型号、板子正反面、商家接线图及原理图。确认 VCC 输入范围、峰值供电能力、TX/RX 电平和 EN 定义。裸模组 VBAT 规格为 3.4–4.5V，不能据旧小板使用 5V 就把新板 VCC 接到 5V。
2. 先只给新板供电，读取 `AT`、`AT+CGMR`、`AT+CMVERSION` 的应答并保存。Luat 标识不能证明出厂固件是当前项目需要的 AT 版本；如果没有对应应答，先核对启动状态、串口参数和固件类型，不立即刷写。
3. 商家提供的 ML307R 维护诊断手册明确覆盖 DC/DL 型号。工具仍须匹配实际固件：取得 USB 驱动、CATStudio 及该版本的 DBG/日志数据库，不能假定旧版本数据库适用。

## 接线原则

| 用途 | 接法与确认点 |
| --- | --- |
| 现有 AT 通话 | 新板 TX → ESP32 模组串口 RX；新板 RX ← ESP32 模组串口 TX；共地。先确认双方电平转换，裸模组 1.8V UART 不直接视作 ESP32 3.3V UART。保留现有模组 UART 配置，雷达 GPIO6/8 不改作模组接口。 |
| USB 内部日志 | 板子 D+、D− 接电脑的原生 USB 数据通道并共地，使用短线/合适转接板。普通 USB 转 TTL 的 TX/RX 不能代替 USB D+/D−。 |
| USB 供电/检测 | USB VBUS 与模块 USB 检测脚的接法必须依据这块小板原理图。图片不能确认；不能把电脑 USB 的 5V 直接接裸模组 VBAT，也不能让独立供电与 USB 电源互相回灌。 |
| EN/复位 | 先查商家定义，再决定是否连接 ESP32；不把 EN 猜成复位输入。 |

第一次对比仍由 UART AT 承载通话，USB 接电脑用于诊断。取得基线后，再另建 USB 数据联网方案的测试批次。

## 先采日志，再做崩溃捕获

1. 确认 Windows 能枚举模组原生 USB 设备及诊断端口。安装匹配驱动；记录固件版本和 USB 设备信息。
2. 按维护诊断工具手册第 14–18 页，在 CATStudio 选择 Generic Target Online，配置 Device Communication 的 USB 连接，再在 Logger 中加载匹配的 Communication/Application 日志数据库。确认设备连接及数据库匹配后开始保存内部日志。
3. 同时保存 ESP32 TTL 日志、App 日志、通话起止时间、AT 发送超时与音频统计。内部日志不能代替这些记录：AFE 是 ESP32 音频链路的告警，新 4G 板也不能保证单独解释它。
4. 在独立诊断批次中确认固件支持后，执行厂家定义的 `AT+MDUMPCFG=1`，使后续死机进入 Dump 保存模式。此命令会改变异常后的行为，不是读取过去重启原因的只读查询。
5. 若发生 Assert/Dump，保留供电，优先取文件；暂停该诊断批次的自动重启/断电恢复，避免破坏现场。按手册第 19–21 页，在 CATStudio → Modules → YmodemDump 中选择异常后出现的端口并 Receive。按手册要求释放占用 modem 端口的工具。
6. 保存 Dump、匹配日志数据库与固件版本，分析可解码的信息；底层断言、私有符号或基带问题可能仍需厂家解码。

## 能得到什么结论

- 固件 Assert/部分软件死机：如果诊断配置生效且供电持续，可能抓到 Dump 与内部日志，明显比只有 `MATREADY` 更有定位价值。
- 掉电、瞬态欠压、外部复位：可能直接重新启动，留不下 Dump；仍需测模组 VBAT、输入和控制脚的瞬态波形。
- AT/网络等待或 ESP32 AFE 积压：结合内部日志与现有时间线判断；没有 Dump 不表示模块没有问题，也不表示已经证明是电源问题。
- 此前未采集的历史重启：不能保证补查。此次接线与配置主要为后续故障保留证据。
